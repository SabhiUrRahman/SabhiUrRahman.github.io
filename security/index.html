(01) The eight checks

  1. 01 · Headers

    Security headers

    Look for
    Open the site, then DevTools → Network → the first request → Response Headers. Look for Strict-Transport-Security, Content-Security-Policy, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, and X-Frame-Options or a frame-ancestors rule.
    Fix first
    HTTPS everywhere with HSTS, then X-Content-Type-Options: nosniff and a referrer policy. If your plan cannot send custom headers, a proxy in front of the site, such as Cloudflare, can add them.

  2. 02 · CSP

    Content Security Policy

    Look for
    A Content-Security-Policy header or meta tag, and the list of outside domains your pages load scripts, styles, fonts, images and frames from.
    Fix first
    Send the policy as Content-Security-Policy-Report-Only first so nothing breaks, read what it reports, then enforce it. Keep the allowed domains few and avoid 'unsafe-eval'. A meta-tag policy cannot set frame-ancestors, so framing protection needs a header.

  3. 03 · Forms

    Forms

    Look for
    Where each form sends its data (the builder, Zapier, a CRM), who receives the emails, and whether spam gets through. Check that no field asks for more than you need.
    Fix first
    Turn on the spam protection your builder offers, send submissions only to inboxes you control, and never ask for passwords or card numbers in a plain form.

  4. 04 · Custom code

    Custom code

    Look for
    Every embed, and every page-level or site-wide custom code block. That code runs with full access to the page and to anything a visitor types into it.
    Fix first
    Remove code nobody can explain. Never put API keys or secret tokens in front-end code: anyone can read them in the page source.

  5. 05 · Scripts

    Third-party scripts

    Look for
    Every outside script: analytics, chat widgets, heatmaps, tag managers. A tag manager can add new scripts later without anyone publishing the site.
    Fix first
    Remove what nobody uses, limit who can publish in the tag manager, and add Subresource Integrity (the integrity attribute) to files that never change.

  6. 06 · Access

    Access

    Look for
    Who can sign in to the builder workspace, the domain registrar, DNS, hosting and the form inbox. Former staff and agencies often still can.
    Fix first
    One account per person and no shared logins, two-factor authentication everywhere (the domain registrar first), and remove anyone who has left.

  7. 07 · Gated content

    Gated content

    Look for
    Password-protected or members-only pages, and the files linked from them. Open those file links in a private window: an uploaded file is often reachable by anyone who has the link.
    Fix first
    Keep truly private files out of public asset storage, and check that gated pages do not show up in search results or the sitemap.

  8. 08 · Backups

    Backups

    Look for
    When the site was last backed up, and whether that copy includes CMS content, form submissions and assets. A backup that lives only inside the builder account is gone if the account is lost.
    Fix first
    Export CMS collections and form submissions on a schedule, keep a copy outside the builder account, and test a restore once.
